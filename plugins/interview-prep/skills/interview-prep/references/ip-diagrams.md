# Strategic Diagram Pack

Optional — runs only when the user asks for a visual (a diagram, a north
star, a deck-ready pack), not by default. Standard/Deep modes only; skip
entirely in Rapid. Produced as a single `.drawio` file (diagrams.net XML)
with one tab per diagram, editable rather than a flat image, saved
alongside the dossier if one is being written (`ip-dossier-template.md`).

## Why drawio, not a flat image

The user can reshape it before or during a real conversation (adjust a
growth assumption, re-tier a pillar) without regenerating from scratch,
and it opens directly in diagrams.net or the VS Code drawio extension.

## Recommended tabs (build only what's asked for; this is the full menu)

1. **North star / capability map** — a small number of capability domains,
   each broken into individual capabilities, color-coded by maturity
   (established / actively being built / genuine gap). The gap list is
   usually close to the actual 90-day plan for the role — say so
   explicitly rather than leaving it implicit.
2. **Architecture / value-chain stack** — the layers data or product
   actually flows through today, annotated with what's genuinely new
   (recently announced/shipped) vs. already live in substance.
3. **Business model** — the real revenue architecture as it exists today,
   distinguishing what's already monetized from what's an emerging or
   underdeveloped revenue line.
4. **Revenue model (modeled)** — only if asked, and only ever with a
   visible, unmissable disclaimer distinguishing the real baseline figure
   (from the JD/recruiter brief/public filing) from anything projected or
   assumption-driven. State the assumptions in the diagram itself, not
   just in a caption — growth rates, cost drivers, whatever the model
   leans on. Never let a modeled figure be quotable as if it were a
   verified fact.
5. **Investment bets** — a table-style tab: each strategic bet, its
   estimated cost/effort, modeled impact, and the specific data point
   behind the "why" — so it can be argued with concretely in the room,
   not just described.
6. **Ecosystem** — names real, researched entities (clients, partners,
   the competitive landscape from Phase 1) in the actual flow, not
   generic boxes — this is where Phase 1's named-research work earns its
   keep visually.
7. **Managed vs. self-serve / build-maturity matrix** — useful when the
   role involves a product maturity or operating-model argument.

## Disclaimer discipline

Any box built from a model, assumption, or inference (not a verified
source) must say so in the diagram itself — a small note or distinct
color is enough, but it must be visible without opening a caption. This
matters more than making the deck look finished: presenting a guess as
verified fact in front of the actual company is the failure mode this
guards against, and it happened once in practice before this rule existed
explicitly.

## Scope discipline

Stop at what was asked for. A single-diagram request doesn't imply
building the full seven-tab pack — offer the rest rather than
auto-expanding scope, the same way Phase 7's dossier is offered rather
than assumed.
