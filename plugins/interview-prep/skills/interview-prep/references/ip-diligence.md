# Late-Stage / Diligence-Level Prep

Applies when the process has moved past initial screening/competency
rounds into final-round, executive, or offer-adjacent territory —
signaled by the transcript debrief (`ip-transcript-debrief.md`), the user
saying so directly, or context like an NDA, a data room, or a
formal-sounding next step. At this stage, generic interview-prep framing
(soft logistics questions, safe open questions) under-serves the
conversation — the user should be operating like they're running
diligence on the role, not just interviewing for it.

## Reframe the question list

Drop recruiter-style logistics questions from the front of the list at
this stage (they've likely already been answered in earlier rounds — see
`ip-transcript-debrief.md`'s reconciliation loop). Replace with a
document/information request list organized like formal due diligence,
grouped under headings such as:

- **Strategy & execution** — current plan, what's tracked against it, what's slipped
- **Technical architecture** — stack, technical debt, scaling constraints
- **Product portfolio** — what's shipped vs. roadmapped vs. shelved
- **Financials & unit economics** — margin structure, customer concentration, churn
- **Commercial & contracts** — key client/partner agreements, renewal risk
- **People & org** — reporting lines, gaps, retention risk
- **Governance & compliance** — decision rights, any regulatory exposure

For each heading, ask for what genuinely can't be reconstructed from
public research alone — prioritize by that test, not by completeness for
its own sake. This list is also a legitimate thing to literally hand the
company as a request ahead of a final round, not just a private prep
document — frame it that way if the user wants to send it.

## Use their own documents against generic prep, if provided

If the company has shared internal documents (a strategy brief, an OKR
set, a risk register, a scoring matrix, an org chart) ahead of this stage:
- Don't paraphrase them back generically — mine them for **internal
  tensions**: places where two of their own documents contradict each
  other, where a stated priority doesn't match where the scoring/resource
  data actually points, or where a plan has visibly stalled (e.g. an OKR
  that's been at the same completion percentage across two review
  periods). A finding built from a contradiction *within their own
  materials* is far sharper than an externally-researched observation,
  and demonstrates a different level of read than any competing candidate
  is likely to bring.
- If a document contains a section where a named stakeholder has
  personally posed open questions (e.g. a "founder's view" or "CEO
  questions" column), treat that as a direct signal of what they actually
  want probed — build a defensible position on each one specifically,
  citing the document's own language back where possible.
- **Scan for duplication before reusing anything** — if asked to build on
  these documents, check whether a point has already been made elsewhere
  in the same materials before restating it; repeating their own content
  back to them reads as padding, not insight.

## What this phase does NOT cover

Building actual engagement deliverables — workshop decks, working
prototypes, a 30/60/90 plan meant to be handed over, formal proposal
documents — is a different job from interview prep and is out of scope
for this skill. If the user needs one of those, that's a separate request
best handled with the `pptx`/`docx`/`artifact-design` tooling directly,
using this skill's dossier as input rather than continuing to expand this
workflow to cover it.
